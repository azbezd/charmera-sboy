# СБОЙ — исследование и модификация мини-камеры

USB-дамп, проверка совместимости и художественная прошивка для **одного исследованного варианта камеры в жёлтом корпусе**, приобретённой как Charmera. Плата `Ax3295B-V3.0`, Buildwin/OpenRISC. Это независимый эксперимент, не официальный проект Kodak/RETO и не универсальная прошивка для всех Charmera.

**Текущий публичный выпуск: 0.9 experimental.** Здесь находятся инструменты чтения, исходники модификаций и точные патчи. Полные заводские образы и личные фото не распространяются: образ собирается локально из собственного совместимого резервного дампа.

## Сначала совместимость

| Образец | USB с microSD | Заводской SHA-256 | Что поддерживается |
|---|---|---|---|
| A: жёлтый, Ax3295B-V3.0 | `0219:3280` | `d599a346…7b42` | Проверенное чтение; патчи для точного полного хеша |
| B: другой экземпляр | `05e3:f12b` | `3a6fa473…c2b` | Сравнение; прошивка A несовместима, публичного ридера B пока нет |

**Цвет корпуса, модель на коробке, VID/PID и название LCD-профиля не доказывают совместимость.** Полные хеши и границы поддержки — в [таблице аппаратных вариантов](docs/compatibility.md).

Опубликованный образ рассчитан на **заменённый ST7735-дисплей исследованного экземпляра A**. Для штатного дисплея он не предлагается. Даже одинаковые шлейфы не гарантируют одинаковый контроллер или распиновку. Для камеры с родным дисплеем можно использовать идентификацию и резервное чтение; не устанавливайте этот вариант вслепую.

## Что меняет СБОЙ

- Компактные русские экраны включения, выключения и подключения USB; оформление штатного обновления.
- Шесть художественных стилей, каждый в двух вариантах контраста: **VHS I/II → ЧЕРНИЛА I/II → СОРТ I/II → ПРИЗРАК I/II → РАЗРЫВ I/II → РАСТР I/II**. Это 6 алгоритмов × 2 контраста, не 12 разных алгоритмов.
- Меню поверх живого изображения: стрелки вверх/вниз, скрытие через 2 секунды после переключения и при снимке. Меню не добавляется в сохранённое фото.
- Обработка сохранённого видео, дата без часов; загрузка часов из `TIME.txt` при старте.
- Инициализация заменённого ST7735. Инверсия, геометрия и RGB/BGR — отдельные настройки.

Ускорение сенсора, увеличение разрешения и повышение FPS не заявлены. Эффекты используют процессор камеры и могут снижать частоту кадров. [Что действительно проверено](docs/validation.md).

## Короткий маршрут

```text
USB + microSD
     |
     v
USB inventory --> unknown hardware? --> STOP / collect evidence
     |
     v
verify descriptors + resident-code fingerprints
     |
     v
SPI read A == SPI read B --> save private factory backup
     |
     v
exact factory SHA-256 + supported replacement LCD
     |
     v
apply bounded patches --> verify complete output SHA-256
     |
     v
DestBin.bin on microSD --> native camera updater at startup
     |
     v
two new SPI reads == intended image --> remove update file
```

Чтение выполняется **по USB через уже работающую прошивку**. Запись выполняет **штатный обновлятор с microSD**. Программатор для этого рабочего сценария не нужен; универсального восстановления мёртвой камеры по USB здесь нет.

### 1. Проверить USB без захвата камеры

Инструменты доступа к устройству сейчас поддерживают **macOS**. Python 3.9+; для чтения понадобится `libusb` (например, `brew install libusb`).

```sh
python3 tools/identify.py --usb
diskutil list external physical
```

Камера A с картой сама входит в накопитель, без меню MEMORY. Без карты наблюдался режим веб-камеры `1908:3282`. Закройте приложения, работающие с картой, перед резервным чтением.

### 2. Сделать резервную копию

Найдите **целый диск именно Buildwin Media-Player** и его размер в байтах через `diskutil info`. Подставьте реальные значения в команду ниже; `diskN` — обозначение, не готовый номер.

```sh
sudo python3 tools/backup.py --disk diskN --card-bytes SIZE_IN_BYTES
```

Ридер дополнительно проверяет единственный Buildwin-накопитель, внешний USB-диск, точный выбранный номер/размер, USB-дескрипторы и код камеры. Он сохраняет два полных чтения по 1 MiB и принимает результат только при совпадении. Пароль вводится в Terminal; скрипт не сохраняет пароль.

После завершения на macOS может потребоваться физически переподключить USB: возврат драйвера накопителя иногда завершается тайм-аутом. Это не команда стирания прошивки. [Протокол и ограничения](docs/protocol.md).

### 3. Определить точную версию и собрать образ

```sh
python3 tools/identify.py camera-dumps/YOUR_CAPTURE/spi-flash-1MiB.bin
python3 tools/build.py camera-dumps/YOUR_CAPTURE/spi-flash-1MiB.bin --lcd replacement-st7735
```

Сборка требует **точного заводского SHA-256 образца A**, а не просто похожих строк. Не снимайте проверку хеша для другого экземпляра. Сохраните оба исходных дампа отдельно от карты камеры. Модифицированный дамп не заменяет заводской backup.

Готовый файл: `custom-firmware/builds/sboy-0.9/DestBin.bin`.

```text
SHA256 3c67c73acb5d34c85da6bd28c6edfef9179c0884505eabe53e99089624cea010
```

Дальше следуйте [порядку установки и проверки](docs/install.md). Сборщик сам не подключается к USB и ничего не устанавливает.

## Вспышка: ручной постоянный свет

**Проверено владельцем: удержание стрелки вниз включает белый постоянный свет.** Повторное удержание выключает его. Это штатная логика; её код сохранён. В 0.3 значки были скрыты по ошибочному предположению об отсутствии светодиода, в **0.9 индикация возвращена**: обычная / перечёркнутая молния.

При обычном и тёмном снимке автоматическая короткая вспышка не наблюдалась. Автоматический режим не добавлялся. [Разбор кода и тест](docs/flash.md).

## Исходники и проверки

```sh
python3 -m unittest discover -s tests -v
python3 -m unittest discover -s tools -p 'test_*.py' -v
```

После сборки локальных образов доступны эмуляторные проверки эффектов:

```sh
python3 -m pip install -r requirements-dev.txt
python3 -m unittest discover -s custom-firmware/tools -p 'test_*.py' -v
```

`custom-firmware/tools/` содержит OR1K-ассемблер, ядра обработки, генераторы меню/графики и исторические пошаговые сборщики. `patches/` содержит только изменённые байты каждого этапа; основной сборщик воспроизводит точные образы независимо от версии JPEG-кодировщика. [Архитектура](docs/architecture.md).

Ошибки и новые аппаратные варианты можно описывать в Issues. Приложите USB-ID, размеры/хеши и версию, но не выкладывайте личные фото, пароли или полные дампы памяти. Не переносите адреса вызовов на другую прошивку без анализа.
