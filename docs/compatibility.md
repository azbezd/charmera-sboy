# Как отличить варианты

Проект начался с двух купленных мини-камер. Внешнее сходство не означало одинаковую прошивку. Подтверждённые сведения относятся к этим двум экземплярам, а не ко всему тиражу.

| Признак | A: жёлтая камера | B: красная камера |
|---|---|---|
| USB MSC | `0219:3280` | `05e3:f12b` |
| SCSI | Buildwin / Media-Player / 1.00 | Buildwin / Media-Player / 1.00 |
| Интерфейс / IN / OUT | 4 / 0x81 / 0x01 | 4 / 0x81 / 0x01 |
| Прочитанный SPI-диапазон | 0..0xfffff, два совпавших чтения | 0..0xfffff, два совпавших чтения |
| Имя LCD-профиля | `st7735S_spi` | `jd9850_spi` |
| Реальные команды родной LCD-таблицы | JD9850-подобные | JD9850-подобные |
| Кастомные патчи этого проекта | 0.9: точный заводской хеш A и заменённый ST7735 | Отдельная rc7: точный хеш B и его родной JD9850 |

Заводской A:

```text
d599a346010f69ac6b7a1c72a69daa0ee35fa3aa9f7d86f454e226e85bfa7b42
```

Заводской B:

```text
3a6fa4735a7bb5a6f302a011ca8332d11121d64a930404533eedd59cb3eb6c2b
```

13 октября повторное двойное чтение B подтвердило точное совпадение с заводским образом после использования общей карты. [Результаты проверки и отличия загрузчика B](red-camera.md).

`1 MiB` здесь — проверенный объём чтения нашего инструмента. Физическая ёмкость второго чипа независимо не измерялась. Название платы A взято из исследования экземпляра; точная модель сенсора программно не установлена. USB-ID, строки прошивки и даже имя LCD-драйвера не являются чтением маркировки чипа.

## Что можно выяснить только кабелем

1. USB VID/PID, класс, дескрипторы, доступность накопителя.
2. На поддерживаемой работающей прошивке — RAM-код и его отпечатки через vendor-команду.
3. После проверки resident SPI reader — полный резервный образ фиксированного диапазона.
4. Из дампа — размер, SHA-256, BLDR-заголовок, build time/date, строки LCD-профиля и совпадение с известными образцами.

Что нельзя обещать: универсальное определение сенсора/контроллера LCD/объёма флеш по одному VID/PID, чтение из любой похожей камеры, восстановление не загружающегося устройства. Неизвестный профиль должен остановить сценарий.

## Родной экран и ST7735

Исследованный заменённый экран: 160×80, окно с отступами 26,1, INVON `0x21`; с 0.7 MADCTL `0x08` вместо `0x00` для RGB/BGR. Геометрия и инверсия проверялись через RAM и на устройстве; окончательное физическое подтверждение цветопорядка после 0.7 пока не записано.

Применять этот LCD-профиль к штатному дисплею нельзя. В репозитории нет автоматически выбранного «универсального экрана». Сборщик явно требует `--lcd replacement-st7735` и точный заводской дамп. Это ограничение относится к сборке A. Для исследованного штатного дисплея B есть отдельная красная сборка с `--lcd original-red-b-jd9850`; настройки LCD A в неё не переносятся.
