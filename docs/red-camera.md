# Красная B: СБОЙ 1.0-rc7

Статус на 13 октября 2026: отдельная экспериментальная сборка rc7 подготовлена, воспроизведена из исходников и проверена чтением файла с карты. Предыдущие эффекты видны на реальных снимках; аппаратное подтверждение исправлений rc7 и полный SPI-readback ещё ожидаются. Патчи жёлтой A к этой камере не применяются.

## Проверка после использования общей карты

После удаления файла обновления с общей microSD прошивка красной камеры была прочитана через USB дважды. Оба образа размером 1 048 576 байт полностью совпали с её исходным дампом: **0 изменённых байт**. Прошивка жёлтой камеры не установилась. Команд стирания или записи flash при проверке не отправляли.

```text
SHA-256  3a6fa4735a7bb5a6f302a011ca8332d11121d64a930404533eedd59cb3eb6c2b
USB      05e3:f12b
SCSI     Buildwin / Media-Player / 1.00
LCD      jd9850_spi, 80 x 160
```

Активная таблица LCD в RAM совпала с заводской таблицей во flash. Сохранены два SPI-образа, RAM, повторное чтение области кода, два чтения окна ROM и таблица SDK. Проверенный диапазон SPI — `0..0xfffff`; это не независимое измерение физической ёмкости микросхемы.

В прошивке присутствуют строки `AX3295B-V2.1` и `20260704-V3.0`. Это разные программные идентификаторы; маркировку физической платы и модель сенсора по ним не устанавливаем.

## Отличия, важные для переноса

| Объект | Красная B |
|---|---|
| Каталог ресурсов, смещение в файле | `0x7f800` |
| Заставка включения, ресурс 11 | `0x9a20d`, 3705 байт |
| Goodbye при выключении, ресурс 10 | `0x99674`, 2969 байт |
| Ресурс 12, ранее ошибочно принятый за выключение | `0x9b086`, 2209 байт |
| Идентификатор обновления, ресурс 15 | `0xbde9d`, `AX3295B-V2.1` |
| Экран USB, ресурс 16 | `0xbdea9`, 2324 байта |
| Таблица LCD во flash | `0x78e84`, 1008 байт |
| Активная таблица LCD в RAM | `0x02096600` |

Ресурсы имеют другие размеры и смещения. Настройки ST7735 из сборки A предназначены для заменённого дисплея и не нужны штатному экрану B. Для B отдельно перенесены вызовы обработки кадров, меню, короткие нажатия и путь эффектов видео. Нативные настройки LCD/сенсора, длинное нажатие для света и штатные JPEG/AVI/аудиофункции сохранены. Реальное видео rc7, звук и FPS ещё требуют проверки.

## Обновление с карты

В исследованном коде обновления B используется то же имя `DestBin.bin`, но другая проверка версии: сравнивается ресурс 15 с данными файла по соответствующему смещению. Равная версия пропускает обновление. Схему с изменением времени сборки A переносить сюда нельзя.

В просмотренном пути перед стиранием flash не найдено отдельной проверки совместимости платы. Это результат статического разбора, а не испытание неправильной прошивки; все вспомогательные функции и альтернативные пути не проверены исчерпывающе. Отсутствие случайного обновления в этом сеансе не доказывает защиту от чужого образа.

**Не переставляйте карту с `DestBin.bin` между камерами.** Храните образы на компьютере и кладите обновление на карту только для конкретного подтверждённого экземпляра.

Жёлтый сборщик по-прежнему отклоняет образ B; для B используется отдельная команда ниже. Публичный USB-сценарий резервного копирования пока поддерживает A; эта проверка B выполнена отдельным исследовательским инструментом с проверками машинного кода. `tools/identify.py` распознаёт сохранённый дамп B и показывает его собственный идентификатор, не читая метаданные по адресам A.

## Собрать rc7

Нужен собственный точный заводской SPI-дамп B размером 1 MiB, сохранённый до изменений. Сборщик проверяет весь SHA-256, не только строки версии или USB-ID. Уже модифицированный дамп и образ A будут отклонены.

```sh
python3 tools/identify.py /path/to/red-factory.bin
python3 tools/build_red_release.py /path/to/red-factory.bin --lcd original-red-b-jd9850
```

Результат: `custom-firmware/red/builds/sboy-red-1.0-rc7/DestBin.bin`.

```text
SHA-256  ccc4d9ff172608e0968099920fe9952ea5f5cea0ce636bcc87c0433c41f51253
ID       SBOY-B-1.6
Size     1048576 bytes
```

Идентификатор штатного обновлятора отличается от публичного названия rc7. Сборка полностью офлайн, без доступа к USB и без копирования на карту. Публичный JSON содержит изменения, полный заводской образ не распространяется.

## Установка именно на красную B

1. Сохраните два совпавших заводских дампа и фотографии отдельно. Убедитесь, что подключена именно исследованная B, и проверьте собранный хеш.
2. Положите `DestBin.bin` в корень её microSD. Сначала сохраните неизвестный предыдущий файл обновления, если он там есть. Сравните SHA-256 файла на карте с указанным выше.
3. Завершите запись и размонтируйте карту. Оставьте USB-питание и microSD подключёнными, выключите и включите камеру кнопкой. Две минуты не отключайте питание и не нажимайте кнопки. После обновления камера может выключиться.
4. Без USB проверьте включение, живую картинку, все 13 режимов, скрытие меню через две секунды, снимки и короткое видео со звуком. При выключении ожидается «СИГНАЛ ПОТЕРЯН» вместо Goodbye.
5. После проверки удалите известный `DestBin.bin` с карты, сохранив копию на компьютере. Не переставляйте карту с обновлением в другую камеру.

Обновлятор стирает flash перед записью; при потере питания рабочий USB может исчезнуть. В комплекте нет универсального восстановления не загружающейся камеры. Равный ID обновлятор пропускает; предыдущий совместимый образ с отличающимся ID можно установить тем же способом. Заводской дамп B возвращает его родной LCD-профиль, не профиль жёлтой A.

## Эффекты и управление

| № | Режим | Характер обработки |
|---|---|---|
| 1 | ВХС | Смещения строк и цветового сигнала |
| 2 | ЧЕРНИЛА | Ограниченная тёплая палитра |
| 3 | ГРАВЮРА | Монохромный штрих |
| 4 | ПРИЗРАК | Смещённое повторение изображения |
| 5 | РАСТР | Точечная структура |
| 6 | ПИКСЕЛИ | Мелкие блоки |
| 7 | ДИЗЕР | Цветовой дизеринг |
| 8 | ЧБ ДИЗЕР | Чёрно-белый дизеринг |
| 9 | ТЕРМО | Тепловая палитра |
| 10 | БУМАГА | Ограниченная палитра и текстура |
| 11 | АСКИИ | Микросимволы, сохранение части исходной яркости |
| 12 | ЛИНИИ | Линейный растр |
| 13 | РЕЛЬЕФ | Перепады яркости по горизонтали |

Короткие ↑/↓ переключают режимы, долгое ↓ сохраняет штатное управление постоянным светом. Меню 64×16 скрывается через 2000 мс и при снимке. Для художественных режимов видоискатель сохраняет больше исходной яркости; итоговое фото обрабатывается сильнее. Геометрия ASCII — 4×4 в буфере эффекта, JPEG может дополнительно масштабироваться. Это не обещание символов 4×4 в конечном файле.

Список больше не содержит контрастных дублей, «Разрыва», «Ризо», «Сорта», «Дуотона», «Осколков», «Хромы» и «Шлейфа». Исключённые алгоритмы могут оставаться в неиспользуемых участках исторического кода, но недоступны из меню rc7.

## Пересобрать исходники и проверить

Для обычной сборки выше дополнительных библиотек не нужно. Для генераторов графики и тестов нужен Pillow; точная воспроизводимость JPEG зависит также от кодировщика. Проверенная локальная среда: Python 3.12, Pillow 12.3.0. Каждый этап проверяет входной хеш; несовпадение останавливает цепочку.

```sh
python3 -m pip install -r requirements-red.txt
python3 tools/rebuild_red_sources.py /path/to/red-factory.bin
python3 -m unittest discover -s custom-firmware/red/tools -p test_red_rc7.py -v
```

Генератор восстанавливает rc1…rc7 из исходников, проверяя хеш каждого этапа. Исторические модули сохранены для воспроизводимости; текущая точка входа — `build_red_rc7.py`. Обычный точный патч не зависит от версии JPEG-кодировщика.

В rc7 13 последовательных UI-индексов отображаются на прежние внутренние алгоритмы с пропуском TEAR. Поэтому остальные эффекты, в том числе мелкий ASCII, не меняются. Тесты выполняют реальные OR1K-инструкции с контролем границ памяти, сравнивают кадры с эталоном, проверяют сохранение регистров, четыре обработчика стрелок, таймер, защиту LCD и нативной логики света. В CI без заводского образа запускается доступная часть проверок; полная пересборка выполняется локально со своим дампом.

Причина старой заставки: раньше заменялся ресурс 12, тогда как JPEG Goodbye находится в ресурсе 10. rc7 заменяет ресурс 10, не меняя каталог и размеры слотов.
