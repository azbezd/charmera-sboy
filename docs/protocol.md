# USB-чтение: что именно происходит

Хостовый инструмент рассчитан на macOS и `libusb`. Linux/Windows-порты не проверены. Стандартный MSC bulk-only transport: CBW `USBC`, CSW `USBS`, интерфейс 4, OUT 0x01, IN 0x81. Номера взяты из конкретного дескриптора A; несовпадение отклоняется.

Перед захватом драйвера проверяются один Buildwin-накопитель, выбранный whole disk, внешний USB, точный размер карты. `sudo` нужен macOS для временного отключения системного драйвера накопителя. На нашем Mac его возврат часто давал `-7`; физическое переподключение восстанавливало устройство. Карта не форматируется.

## Этапы доверия

1. Дескрипторы и стандартный SCSI INQUIRY должны совпасть с исследованным устройством.
2. Vendor CDB `0xCD` вызывает SDK helper `0x118` для чтения таблицы по `0x100`, 512 байт. Этот начальный vendor-запрос сам по себе **не универсально безопасен для неизвестной прошивки**: на несовместимой камере возможен зависший сеанс. Не запускайте по одному внешнему сходству.
3. Таблица читается дважды; инструкция по `0x118` должна быть OR1K jump на `0x020420f4`. Затем проверяются SHA-256 helper и первых 4096 байт RAM-кода.
4. Проверяются три диапазона resident SPI reader и USB-буферы. Только после этого доступен SPI READ.
5. Флеш 0..0xfffff читается по 512 байт дважды. Проверяются каждый CSW/tag/residue/status, длина, BLDR-заголовок и полное равенство.

## Формат vendor CDB

```text
byte  0      : CD
bytes 1..4   : little-endian helper (0x118)
bytes 5..8   : source address or FFFFFFFF sentinel
bytes 9..12  : secondary callback or FFFFFFFF
bytes 13..15 : bounded 24-bit parameter
```

Чтение SPI использует только fingerprinted callback `0x02040078`, связанный с командой SPI `03h`. Его адрес не переносим на другую прошивку. Все данные полезной нагрузки идут от устройства к хосту; отправляемые CBW — команды чтения. Код записи/стирания флеш, загрузки исполняемого кода и произвольного вызова GPIO не реализован.

Важно различать RAM/ROM snapshot и SPI backup: образ памяти работающей программы нельзя положить на карту как `DestBin.bin`.

## Штатная установка

Обновлятор A находится по `0x02014388`, первоначальный вызов из приложения — `0x02000ae8`. Он открывает `DestBin.bin`, сравнивает время/дату в области `0x8c030`/`0x8c044`, стирает SPI, пишет основную часть с байта 512, заголовок последним, затем читает для проверки. В СБОЙ менялись четыре UI-цвета обновлятора, не его алгоритм стирания/записи. С 0.5 вызов обёрнут для последующего запуска парсера часов.

Этот проект не использует найденные в сторонних инструментах команды переключения в loader, стирания или записи USB: они требуют отдельной проверки.
