# Освещение и значок вспышки

## Результат на 2026-10-13

Владелец подтвердил: **долгое нажатие стрелки вниз включает белый постоянный свет**. При обычном и тёмном снимке до ручного включения белая вспышка не наблюдалась; синий индикатор питания горел.

В 0.9 восстановлены значки света. Весь исполняемый код побайтно совпадает с 0.8, а обработчики освещения — с заводским дампом. Пользователь специально выбрал сохранение штатной логики. После установки 0.9 владелец подтвердил: свет работает, значок меняется. Полный SPI readback этой версии ещё не выполнен.

Официальная [инструкция Kodak/RETO Charmera](https://www.kodak.retopro.co/pages/kodak-charmera-keychain-digital-camera-quick-start-guide) упоминает вспышку при снимке. Это не доказывает идентичность нашего образца официальной камере: прошивки и аппаратные варианты различаются.

## Что делает конкретная заводская прошивка A

Адреса ниже — RAM-адреса только для известного заводского SHA-256. Смещение кода в файле: `address - 0x02000000 + 0x2400`.

| Адрес | Наблюдаемое поведение |
|---|---|
| `0x02009138` | Фото: читает состояние, переключает 0/1, сохраняет настройку `0x15`, обновляет значок |
| `0x0200e484` | Видео: аналогичное ручное переключение |
| `0x02014e84` | Передаёт в GPIO-функцию банк 0, маску `0x0008`, состояние 0/1 |
| `0x02014ec0` | Читает этот вывод |
| `0x0202dea8` → `0x02020fbc` | Записывает выбранный бит выходного регистра; не трогает соседние биты |
| `0x0201530c..0x02015334` | При удержании события `0x20` генерирует `0x21` |
| таблица `0x02082bd8` | Событие `0x21` связано с `0x02009138`; короткое `0x20` переключает эффект вперёд |

Настройка имеет значения `0x81000014` / `0x81000015`, а UI использует ресурсы 20 / 21. При входе в режим фото включённое состояние восстанавливается. Это похоже на ручной постоянный свет; найденная ветка не реализует автоматическую импульсную вспышку по уровню освещённости.

Ключевые диапазоны кода (`09138+98`, `0e484+70`, `14e84+58`, `2dea8+58`; адреса с префиксом `02000000`) побайтно совпадают между заводским дампом и 0.8/0.9. В 0.3 картинки 19–21 заменены прозрачными: прежнее предположение об отсутствии вспышки не было аппаратно доказано.

## Тест без перепрошивки

1. Отключить USB, включить обычный режим фото.
2. Долго нажать кнопку, которая коротким нажатием переводит на следующий эффект, затем отпустить.
3. Посмотреть на переднюю сторону: появился ли постоянный белый свет. Повторить то же нажатие для выключения.
4. Если неясно, какая стрелка соответствует направлению, проверить обе по одному разу. Наблюдать физический свет, не полагаться на скрытый значок.
5. Зафиксировать результат. При отсутствии света нельзя заключать только по коду, что светодиод выпаян, сломан или отсутствует.

Прямое переключение неизвестных GPIO и перебор выводов не входят в этот тест. Публичный USB-ридер не содержит команд включения выводов или записи прошивки.

## Красная B: постоянный свет и импульс при снимке

На B владелец наблюдал вспышку во время снимка при перечёркнутой молнии. В заводском коде это два отдельных состояния: значок 27/28 показывает постоянный свет (`UI+0x74`, настройка 13), а ветка снимка читает настройку 14 и может включать тот же свет на время съёмки. Поэтому перечёркнутая молния не означает запрет импульса при фото.

Обработчики фото `0x020169c0..0x02016be4`, долгого ↓ в фото `0x02016fd0..0x020170bc` и видео `0x02018620..0x02018720` побайтно сохранены в красной rc7. Эти адреса относятся только к B. Логику белого света не заменяли; прямой перебор GPIO не выполнялся.
